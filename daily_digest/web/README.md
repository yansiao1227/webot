# 每日观察网页

React、Vite和TypeScript组成的轻量报纸网站，普通CSS适配桌面与手机。宽窄屏共用报纸头版结构，通过媒体查询调整分栏、字号与间距；页头下方不设栏目导航，报道与市场通过内容链接进入，往期入口位于页尾。首页与标题使用本机可用的宋体字族，详情正文使用常规字重的无衬线字族，以字体、字号、字重和颜色区分层级，不从外部服务下载字体。固定首页展示最新正式日报，每期保留永久地址；本地使用Node.js与SQLite持久保存日报；网页与后续托管版本复用同一Worker接口校验和CRUD逻辑，日常更新不重建前端。

首页采用头条配图、分栏短讯与两地市场组成的报纸头版。AI头条优先选取有配图的报道；新闻详情页有图即显示。“内地与香港”优先将有相关配图的报道排在第一条，并在栏目图片区展示其配图；本期该栏所有报道均无可用配图时才使用通用城市插画兜底。窄屏图片区位于第一条新闻上方，按原比例完整显示，宽屏保持位于报道下方。报道使用短标题与较完整的摘要；涉及传闻或否认的标题保留核实状态。首页报道标题允许自然换行，完整显示精简后的标题，详情页保留完整原标题。摘要与正文双端对齐，不设首行缩进；链接不使用箭头。首页不设本期导读，头条直接接在报头下方；内容区在报头下方与底部报道数量／阅读说明上方采用双粗线，板块之间采用单粗线，条目之间采用细实线；社会观察普通卡片不设底部细线，第2、5篇采用线框卡片与深色标题条强调，其余报道不加外框；其他普通列表末项不加底线。板块末尾不叠加卡片底部留白与板块间距，末尾内容距下一板块分割线统一保留20px；底部将品牌、报道数量、来源说明和往期入口合并为紧凑页尾，双粗线位于整个页尾上方。报道通过可点击标题进入详情，不另设“继续阅读”入口，“阅读说明与来源”统一放在页面底部；两地市场不另设“阅读全文”入口，市场摘要按市场名称、代表指数点位和涨跌幅排列，共用当期日期；点击可查看行情详情。点击新闻进入独立报道页，阅读完整原标题、事实、背景、影响、待核实内容及来源；市场数据与本期采集限制分别在子页面查看。日期页和每篇报道的链接固定归属该期日报，不会随首页更新切换内容。

子页面延续纸张底色，标题保留粗体宋体，正文使用常规字重的无衬线字族与较柔和的文字颜色，配合紧凑的段落间距区分阅读层级。报道详情不重复展示首页摘要；来源单独分区并显示来源编号。子页面文字链接使用棕红色，仅“同版继续读”链接保留下划线，手机端同步调整字号和留白。

## 本地使用

以下命令在本目录执行，需要Node.js 22.19或更高版本（使用内置node:sqlite）：

```powershell
npm ci
npm run check
npm test
npm run build
npm run preview
```

启动后打开 `http://127.0.0.1:4173/` 查看本地正式日报，`http://127.0.0.1:4173/preview` 查看明确标记的模拟排版。首次启动的正式首页为空态，归档返回空列表；不会自动把模拟样本写入日报表，也不会触发朋友圈发布。

开发样式时，先启动上述本地服务，再在另一个终端运行 `npm run dev`。Vite 默认通过 `http://127.0.0.1:4173` 代理 `/api`，让开发页面也能读取同一份正式日报；如更改后端端口，需同步调整 `vite.config.ts` 中的代理目标。正式阅读入口使用4173端口，5173端口用于开发热更新。

服务仅监听 `127.0.0.1`，不需要Sites、Cloudflare或D1在线服务。数据库默认保存在本目录 `state/preview.sqlite`；重启保留数据。预览启动时通过Node内置 `process.loadEnvFile` 读取仓库根 `.env`。使用 `DAILY_DIGEST_PREVIEW_DB` 指定另一份本地数据库，用 `DAILY_DIGEST_PREVIEW_PORT` 更改本地端口；兼容旧名 `DIGEST_PREVIEW_DB` / `PORT`。已有进程环境优先于 `.env`，同一来源中命名空间字段优先；相对数据库路径按仓库根目录解析。不要将此预览服务直接暴露到公网。

未设置 `DIGEST_PUBLISH_TOKEN` 时服务仅允许读取，任何写入都被拒绝。需要在本地测试正式内容写入时，由操作者给服务进程配置至少32字符的发布凭据；调用者通过Bearer传递相同凭据，凭据不写入浏览器或日志。Ctrl+C正常关闭预览服务。

已有真实生成的日报时，可在本目录运行`npm run preview -- --edition ../state/local-edition/edition.json`。启动前通过共享API校验并导入本地数据库，再按日期与摘要读回；同日期不同内容会报错，不覆盖历史。此导入无需设置发布密钥，不给HTTP接口增加写入权限，不连接公开站点或微信。`edition.json`由上级目录的[真实生成命令](../README.md#真实生成与本地阅读)产生；模拟样本不可导入。

## 页面与接口

| 地址                                           | 用途                                         |
| ---------------------------------------------- | -------------------------------------------- |
| `/`                                            | 最新正式日报；旧一期保留日期提示             |
| `/daily/YYYY-MM-DD`                            | 当期永久链接                                 |
| `/daily/YYYY-MM-DD/article/ARTICLE_ID`         | 单篇完整报道与来源                           |
| `/daily/YYYY-MM-DD/analysis/INDEX`             | 单篇观察手记（索引从0开始）                  |
| `/daily/YYYY-MM-DD/markets`                    | 两地市场完整数据及缺项                       |
| `/daily/YYYY-MM-DD/notes`                      | 编辑说明、采集限制和全部来源                 |
| `/archive`                                     | 日期倒序的分页归档                           |
| `/preview`                                     | 模拟排版样本                                 |
| `GET /api/editions/latest`                     | 最新日报对象                                 |
| `GET /api/editions?limit=20&cursor=YYYY-MM-DD` | 历史列表；游标使用上一页返回的 `next_cursor` |
| `GET /api/editions/YYYY-MM-DD`                 | 指定日报对象                                 |
| `PUT /api/editions/YYYY-MM-DD`                 | 幂等写入正式日报；需发布凭据                 |

发布接口要求 `Authorization: Bearer <发布凭据>`，服务端秘密变量为 `DIGEST_PUBLISH_TOKEN`，D1绑定为 `DB`。正文最多1MiB，正式接口拒绝模拟内容、缺少来源的新闻、错误交易日、非法排名及内容摘要不匹配。同日期同摘要重复提交只返回原结果；不同摘要返回409，不覆盖原版。

内容摘要使用移除 `content_hash` 后递归按字段名排序的紧凑JSON与SHA256，跨语言约定见上级项目的内容契约实现。网站不渲染模型生成的HTML，引用链接仅接受公开HTTP(S)来源。

## 新闻配图

采集新闻正文时，尽量从同一原文页面的公开图片元数据及正文中提取相关图片，排除可识别的站标、头像、推荐区与小缩略图。配图信息保存在来源的可选 `image` 字段中，包含公开图片地址、替代文本和来源；由采集程序绑定，不由模型编造。没有可用图片时不强行配图。自动提取不能完全替代人工相关性核对。

既有人工核对的本地配图继续按[src/assets/news-media.json](src/assets/news-media.json)中的来源URL精确匹配并优先使用；其余原文图片由浏览器从公开地址加载，可能受源站防盗链或图片失效影响。详情图加载失败时隐藏；栏目配图失败时继续尝试其他有图报道，全部不可用才使用通用插画。

本地图像随前端一起构建，动态原文配图需要访问第三方图片服务；图片不显示图注或图源文字，保留替代文本；图片出处保存在配图元数据与配图说明中。头版头条标题采用普通文字样式，不使用深色底或外框。网页采用WebP压缩，保留原尺寸与构图。移动端的头版与详情页均按图片原始比例显示，随宽度自动调整高度，不裁剪图片。原图出处、使用范围及生成提示词见[配图说明](src/assets/ASSETS.md)与[插画提示词](src/assets/IMAGE_PROMPTS.md)。来源原图的公开转载授权尚未核实，当前仅用于本地预览；自制插画不代表真实现场或项目。

## 构建与后续迁移

代码检查由[Oxlint](https://oxc.rs/docs/guide/usage/linter.html)负责，格式化由[Oxfmt](https://oxc.rs/docs/guide/usage/formatter.html)负责，规则分别在`.oxlintrc.json`与`.oxfmtrc.json`维护。在本目录执行：

```powershell
npm run lint          # 检查JavaScript、TypeScript与React代码，警告也会使检查失败
npm run lint:fix      # 应用可安全自动修复的lint问题
npm run format        # 格式化源码、配置与文档
npm run format:check  # 只检查格式，不写文件
npm run typecheck     # TypeScript类型检查
npm run check         # 依次运行lint、格式检查与类型检查
```

格式统一使用两空格缩进、单引号、分号和LF换行。运行数据、依赖、构建产物、托管元数据、数据库迁移、测试样本和npm锁文件不参与格式化；锁文件通过npm维护。修改代码后运行`npm run check`、`npm test`与`npm run build`。

前端参考[活动H5项目](https://github.com/iftechio/podcast-web-fe/tree/feat/runrunrun/packages/podcast-campaign-runrunrun)按职责组织：`src/main.tsx`装配React与HeadlessMantineProvider，`src/App.tsx`处理路由和日报加载，`src/pages/`存放页面，`src/components/`存放页框、报道内容和市场组件，`src/utils/`存放日期格式化工具。共享报纸样式与响应式媒体查询位于`src/style.css`。

Mantine采用headless模式，不导入默认组件CSS；归档按钮使用UnstyledButton。页面布局与视觉由项目CSS维护，报道、市场和来源接口不依赖组件库。

`npm run build`先构建React，再将前端资源内嵌为Worker ESM，输出 `dist/server/index.js` 和部署清单。Sites项目身份保存在 `.openai/hosting.json`；保留现有身份，不为更新创建新站点。

数据库迁移位于 `drizzle/`，对应的本地SQLite测试schema位于 `migrations/`；已有迁移不可改写。Sites打包工具将迁移复制至产物的 `.openai/drizzle/`，在部署时应用。请求处理器不会创建数据库表。

公开访问使用[服务器部署流程](../deploy/README.md)：通过 SSH 上传构建产物和正式内容快照，Docker 服务监听公网 HTTP 80 端口。每次更新后需运行部署命令同步服务器，公网只提供阅读接口。既有 Sites 构建清单保留；本地预览不会自行部署。公网 HTTP 检查与微信内访问验收分别进行。

自动配图的绑定缓存由 `PUT /api/media/<sha256>` 写入、`GET /media/<sha256>` 公开读取，前端保留同源 CSP。首页头条始终提供图片，优先选用有新闻配图的条目；科技短讯只展示两条。详情页仅展示可用新闻图片，缺图或加载失败时省略图片区。主题图片与首页插画保留类型标识。`--edition` 导入时自动读取日报相邻 `media/` 目录，先导入图片再导入日报；旧 SQLite 自动添加媒体表，不删除历史。预算、失败和恢复规则见[日报说明](../README.md#自动配图)。
