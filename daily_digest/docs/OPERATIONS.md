# 日报接口与运维

## 内容契约

日报包含`schema_version/date/cutoff_at/title/intro/teaser/highlights/articles/analysis/sources/markets/warnings/simulation/content_hash`。AI与社会条目关联采集来源ID，行情分别保存A股和港股的交易日期、分类、指数及涨跌榜。

每栏至少3个独立可核实事件；模型不能新增来源、修改行情快照或填造缺失值。日期、来源时间、URL、文本长度和行业排名经程序校验。默认AI来源包括OpenAI、Google AI、MIT、Hugging Face、NVIDIA、Microsoft和量子位，混合主题源还需通过AI主题关联检查；只采用可读取的原文正文，读取失败不使用摘要补数。公开源不保证长期可用；工作日行情落后且节假日未核实时标为不可用，不猜测休市。港股指数与完整12行业集合使用已核实的恒生官网公开数据，校验日期、行业集合与快照时间。港股接受当天16:00及以后的官方快照并显示实际时间，不要求时间戳达到16:10；16:00前、日期不符、未来时间或行业集合不完整时保留缺项，不替换其他分类。两地已核实休市日可在本机sources.market_holidays配置。

来源可选 `image` 保存从该原文页面提取的公开图片URL、caption和credit，经过与来源一致的封套校验；旧日报无此字段仍可读取。图片获取失败不改变新闻正文或触发模型重跑。

来源时效按采集完成后的最终截止时间校验，读取期间越过24小时窗口的条目会从来源与新闻候选同步剔除；生成前再次检查已有快照。模型输出schema为每栏绑定该栏来源ID枚举，新闻引用不跨采集栏目补数；深度解读可以交叉引用两栏已采集来源。

模拟样本`simulation=true`不得上传生产。React固定组件转义渲染正文，不执行模型HTML。摘要排除`content_hash`后计算递归键排序、无空白、UTF-8 JSON的SHA256，数值规范化与JavaScript一致。

## HTTP接口

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/editions/latest` | 最新一期，没有日报时404 |
| `GET /api/editions?limit=20&cursor=YYYY-MM-DD` | 日期倒序分页 |
| `GET /api/editions/YYYY-MM-DD` | 读取指定日期 |
| `PUT /api/editions/YYYY-MM-DD` | Bearer密钥保护的有界JSON更新 |

同日期同摘要幂等，不同内容409，不能自动覆盖。按完整保存的最大日期展示首页，补录旧日期不倒退。业务层上传后匿名读回日期、摘要和永久链接，成功后才可发朋友圈。

上表中的PUT仅适用于可选HTTPS API部署；当前SSH快照服务器公网只允许GET/HEAD，不开放PUT，自动更新通过下文的SSH发布器完成。

## Sites部署

站点唯一标识与D1绑定保存在`web/.openai/hosting.json`，后续复用该标识。按Sites技能进行独立源码同步、构建、打包和版本部署，只上传web源码，不上传微信代码、state或凭据。Worker产物为`web/dist/server/index.js`，前端资源内嵌，D1的editions表保存日报。Drizzle迁移随归档一起部署，禁止在handler建表、删除历史或重放已应用迁移。

云端秘密`DIGEST_PUBLISH_TOKEN`与本机DPAPI的publish_token保持一致；不进入源码、浏览器、hosting manifest或日志。迁移时导出日报JSON和执行账本，保留永久链接或重定向。换站后重新手机验收，不清库或换ID绕过失败。

## 故障处理

收到账号风控提示时，先暂停日报及MCP新写入，保留请求与原生结果，禁止换ID、改文案重试或自动解除暂停。一次请求、低频和格式调整均不能证明安全；原生DLL注入及远程线程调用本身仍有兼容性和客户端检测风险。`thread_error`为本机远程线程结果，不能当成服务器风控错误码；`calls/submitted/completed`全零也不应被用作自动重发依据。公开网页可继续独立访问，恢复朋友圈须人工核查；本项目不提供规避平台检测的保证。

status/runs核查原执行，preview只查看结果。模型执行未知不重跑；上传响应丢失先精确读回；朋友圈未知只查询原意图。超过当日截止不补发。暂停不取消已提交朋友圈，也不自动解除MCP风控暂停。单期失败不应使普通回复离线。

`status`与Codex服务心跳显示执行阶段、计划时间、截止时间、历史同步、发布器本机状态及朋友圈确认状态；读取这些状态不会触发SSH、模型或朋友圈调用。首次手工部署尚无任务映射时，用部署CLI的`--status <发布ID>`查询网站发布；不为显示状态补造自动意图。MCP明确暂停时保留冻结正文与原意图，标记`mcp_paused`，每30秒只读核对策略；18点仍未恢复则过期。

上线先本地回归，再验证公开访问与真实更新读回；国内手机微信须用户实际确认，随后activate并正常重载Codex服务，不发送即时测试朋友圈。

采集读取总预算240秒，业务层等待上限300秒或当天截止（取更早）；模型线程创建限60秒，日报轮次最多1200秒，独立于普通微信回复的600秒。日报启动限60秒、决定等待120秒、推理180秒、正文停滞60秒；持续输出只续期停滞时限，不能突破总预算。超时错误保存为`ModelTimeout:<阶段>`，保留原轮次ID，不自动重试。网站写入结果未知时保持website_unknown，每60秒核查原发布：HTTPS模式仅GET原日期，404也不自动补PUT；SSH模式查询原发布ID并核对公网，已切换版本可完成确认，不创建新版本或重新切换。到18点停止当期朋友圈发布，保留结果供人工核查。

`generate --output-dir <新目录>`是独立本地流程，不进入上述发布账本。`generation.json`保存阶段、线程/轮次ID及超时阶段，`events.jsonl`只记录事件类型、耗时及增量字符数，不保存推理内容；`generated.json`在内容校验前保存，校验成功才写`edition.json`。使用已完成轮次的落盘结果核查格式失败，不重新调用模型；输出目录不可复用来掩盖未知执行。`--packet`用于明确重用已采集快照，保留原截止时间和数据缺项。

## 本地预览与公开部署条件

本地预览使用Node内置SQLite，不要求Sites服务。只监听回环地址，/preview展示明确的模拟样本，不自动填入正式日报或创建朋友圈意图。

本地预览不启动朋友圈任务。生产可选择已核验的SSH只读快照服务器或HTTPS写API；前者不要求Sites域名或HTTP发布凭据。设置正式地址并完成国内手机微信访问验收后才激活，换地址时需重新验收。不能以服务器HTTP可达推断微信内可访问。

## SSH快照自动推荐

`publisher=ssh_snapshot`用于公网HTTP只读服务器。`DAILY_DIGEST_DEPLOY_HOST/USER/IDENTITY_FILE`指定SSH身份，`site_url`必须绑定同一主机的HTTP80或HTTPS443地址；该模式不使用`publish_token`。`publisher=http_api`保留原HTTPS鉴权写API，不因SSH模式放宽其传输规则。

执行顺序为正式媒体与日报校验导入本地库、冻结全量快照、持久发布ID、SSH候选验证与两阶段切换、匿名核对日期／摘要／媒体，最后才允许MCP投递。已提交朋友圈未知始终只查原意图，即使暂停或过18点仍可只读核对，不自动补发。

首次启动先核对已部署历史，保存独立history表，不能伪造runs表示已发朋友圈。跨日仅排除正式日报实际引用URL；同日已有合法版复用原版，不覆盖或调用模型重写。历史暂不可读时等待核查，不生成可能冲突的新版本。配图后、线程创建后及正文提交前再次核对暂停／停止／截止，正文预算最多1200秒且受18点窗口剩余时间约束。

详见[服务器部署](../deploy/README.md)。该方式不要求启动本机预览服务器；独立导入命令`node daily_digest/web/scripts/import-edition.mjs --db <数据库> --edition <正式日报JSON> --media <媒体目录>`完成后退出，只写本机数据库。它与HTTP API共用内容和图片校验；模拟内容、同日冲突和坏媒体不得进入发布快照。

## 图片缓存与恢复

日报配置 `image_search_budget_seconds` 默认 300 秒，覆盖下载、批量检索和视觉核对，并受自动发布时间窗口约束。恢复沿用原配图截止预算及 `images.json`，已完成结果不重复调用模型；pending/unknown 轮次不重放。不要删除这些记录以重新触发任务，也不要修改原 `captured_at` 或 `cutoff_at` 延长时效。

媒体与日报共用发布凭据：`PUT /api/media/<sha256>` 需要 Bearer 鉴权，正文为 `image/webp` 二进制，最多 512 KiB；检查内容摘要、WebP头与尺寸，按摘要幂等保存。程序端在上传前完整解码并重新编码，服务端不提供外部地址下载或代理。公开 `GET /media/<sha256>` 返回不可变图片及长期缓存头。绑定媒体必须先存在，随后才允许 `PUT /api/editions/<date>`；日期/内容摘要冲突规则不变。

本地 SQLite 自动从版本1升级至2并保留历史记录。D1 执行新增 `web/migrations/0002_media.sql`（Sites/Drizzle 对应 `web/drizzle/0001_media.sql`）；媒体表契约为 `media(sha256 TEXT PRIMARY KEY, body BLOB NOT NULL, content_type TEXT NOT NULL)`。D1部署需先迁移再运行新写入器；SSH方式使用经过校验的完整SQLite快照。

本地预览 `--edition` 会读取日报旁的 `media/` 并通过同一API导入，导入失败不会写入该日报。浏览器保留现有CSP；首页头条优先选择有新闻图片的条目，并始终保留图片或插画；详情页缺图或图片加载失败时省略图片区，不使用插画兜底。排查时分别检查原图下载、视觉判定、媒体PUT、日报PUT和浏览器实际加载，不用某一层成功推断全部成功。

图片排查时，`review_incomplete` 表示模型未返回该候选的判定，`review_reject` 表示明确拒绝，`review_unverified` 表示证据不足；三者均保留图片摘要和原轮次。审核按最多4张的小批次直接附图输入，所有候选必须逐张判定。原文有图但未展示时先检查这些记录，不把页面图片加载成功当成原图覆盖率验收。

`news[].image_provenance` 保存原文HTML提取证据（原页、图片URL、页面SHA-256及图片标签），仅作审核上下文，不改变公开事实来源。程序已核实的原图关联可以直接用于视觉审核；模型联网工具再次访问失败不能作为丢弃该关联的理由。正文图缺失时仍不能拿推荐区图片冒充原图。
