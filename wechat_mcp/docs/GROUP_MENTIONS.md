## 硬性门禁

- 私聊继续受账号及会话白名单约束。
- `conversation_id` 以 `@chatroom` 结尾的事件，必须同时满足：mentions.state=known、mentions.source=weixin41930_record_source_180，且 wxids 数组明确、完整匹配当前账号。
- 缺失/unknown、只 @其他人、只 @所有人、正文出现“@我”或昵称，全部拒绝。
- webhook 发布和投递前都检查。`reply_text` 再检查原始持久事件；即使 agent 已知历史 event_id、忽略提示词或直接调用工具，也不能越过门禁。上下文采集另用账号及会话白名单校验。工具不接受由 agent 提供的 mentions/recipient。
- 发送前仍核验登录账号；原来的单事件唯一回复意图和 unknown 不重发规则保持。

`bridge_status.group_reply_policy` 报告实际门禁。合法事件的 mentions 会随 webhook data 投递，`get_message` 可取得完整原事件。旧 inbox 中不含可靠元数据的群聊记录不能用于新回复；升级不补发已过滤消息。

元数据来自受 bearer 保护的本机上游，而非消息正文或模型判断。此限制针对本 MCP；直接持有 client_hook HTTP 凭据的调用者仍有其独立的发送权限。

## Dot 配置

Dot 保持现有两会话订阅。群聊由 MCP 先过滤，Dot 也核验元数据；禁止用 @昵称文本代替结构化名单。更换支持 stdio/HTTP 的其他 agent 时，相同门禁继续生效，不依赖 Dot 提示词。
