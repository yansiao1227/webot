## 目标与验收范围

在本目录内实现 Windows 微信 **4.1.9.30 x64** 的消息接口，供 agent 和普通程序通过本地 HTTP 调用。完整目标是对齐参考文档的消息发送与接收能力，包括文本、图片、语音、文件及相关下载、解码与历史消息查询。按阶段交付：**本期先实现私聊和群聊文本收发，以及实时或伪实时获取最新未消费消息的接口**；其余消息类型和配套能力保留为后续阶段，不能从总体范围中删除。保留现有 CLI 与 NDJSON 接收方式。

agent 可立即查询已采集但尚未确认消费的消息，也可通过长轮询等待新消息。新消息持久化后立即唤醒请求；`timeout=30` 是最长等待时间，不是每 30 秒才查一次。服务独立持续采集，agent 暂时离线不影响保存。

参考资料：

- [PCWeixinHook 接口文档](https://www.showdoc.com.cn/PCWeixinHook/11559060626558382)：路由、业务参数和消息类型。
- [WeChat-Hook](https://github.com/aixed/WeChat-Hook)：模块划分、路由与原生业务代码组织方式。
- 本目录的 `RESIDENT.md`、版本 profile 与现有收发实验：4.1.9.30 的调用和验证依据。

文档面向 4.1.10.27，不能直接沿用其偏移、ABI 或对象布局。每项新增原生能力必须分别完成 4.1.9.30 适配和验证。参考文档中与消息无关的好友管理、朋友圈、公众号管理、多开、设备环境修改、独立登录和任意数据库执行接口不在本期范围。批量检测好友状态不属于发送消息，本期不实现。

## 当前基础与组织结构

现有 v2 已有驻留 DLL、指定会话文本采样、重复启停和入口恢复机制；真实消息证据主要是一条测试群文本，不能据此推断全会话和全消息类型已验证。现有发送实验只验证过固定目标、固定文本的一次提交，不能直接作为通用发送实现。

所有实现、构建脚本、测试、版本资料、必要依赖、示例与说明集中在 `client_hook` 内。采用以下分工：

| 部分 | 职责 |
| --- | --- |
| `native/` | 驻留引擎、消息快照、客户端队列调度、发送及上传能力、跨进程协议 |
| `api/` | Python 标准库 HTTP 服务、参数适配、消息存储、消费者与回调投递 |
| `client/` | Python 客户端、CLI 和 agent 使用示例 |
| `profiles/`、`vendor/` | 固定版本资料、依赖源码、许可证和来源记录 |
| `tests/`、`examples/` | fixture、接口与存储测试、回调及长轮询示例 |
| `build/`、`state/` | 默认构建产物、SQLite、进程登记及运行记录，不作为源码提交 |

将现有 PE 解析、进程检查、文本快照及需要复用的发送逻辑纳入目录，解除对项目外部 `cli/`、`tools/`、`src/receive_stream/`、其他实验和历史 `work/` 产物的运行与构建依赖。保留来源与许可证，不移动或覆盖已加载的旧 DLL。外部可配置输出目录；仅复制本目录后也应能够构建并运行测试。

Python 进程负责 HTTP、SQLite 和外部回调，DLL 负责微信内部调用。Hook 回调只执行有界复制和非阻塞入队，不执行网络、磁盘写入或等待 agent。原生消费者将自有快照交给 Python 服务落盘；必须保留队列满、服务断开和落盘失败的明确诊断。

## HTTP 与 agent 调用约定

默认监听 `127.0.0.1:30001`，仅附加到已运行且版本匹配的客户端；出现多个候选时要求指定 PID。服务启动后持续采集，agent 是否正在等待消息不影响采集生命周期。agent 退出不停止服务，服务退出或故障则关闭采样并恢复入口。

本期使用 Python 标准库 HTTP 服务与 SQLite，不要求额外安装 Web 框架。服务使用有界请求并发；长轮询使用独立并发配额，不能占满发送和状态接口。默认允许最多 16 个长轮询连接，超出返回 429。非回环监听必须显式配置访问令牌；SDK 支持 Bearer 令牌。不开启默认跨域访问。

提供 `/openapi.json`、接口说明、`client_hook.py` 入口以及 Python 客户端。入口包含 `serve`、`status`、`send`、`listen` 子命令；`listen` 封装取消息和确认流程，不需要用户编写定时轮询任务。旧 `scripts/receiver.py events/status/stop` 保留兼容入口；独立 NDJSON 采样与 HTTP 服务共用目标互斥锁，同时启动时明确拒绝，不能安装两个接收 Hook。

### 发送与基础接口

以下为完整目标接口清单。本期实现文本发送、登录状态、自身资料和状态/结果查询；群 @、无源变体、附件、上传及其他业务路由在后续阶段交付。未交付路由不宣称可用，OpenAPI 和能力状态应明确所属阶段及实现状态。

业务接口均为 `POST` JSON；扩展状态和查询接口使用 `GET`。文档业务参数优先保留，别名在适配层归一化；除文档明确规定优先级外，同一字段的多个别名取值冲突返回参数错误。

| 路由 | 实现要求 |
| --- | --- |
| `/IsLoginStatus` | 已确认登录返回 `onlinestatus="3"`，已确认未登录返回 `"1"`；无法确认时返回明确错误 |
| `/GetSelfProfile` | 返回真实自身 wxid 和经验证资料，未取得的可选资料为 `null` |
| `/SendTextMsg` | `toid`、`msg`；兼容 `wxidorgid` 和 `content`，支持私聊、群聊及 `filehelper` |
| `/SendTextMsg_NoSrc` | 无源文本与 XML `atlist` 形式的群 @；两篇文档共用该路由，不重复注册 |
| `/SendAtMsg_NoSrc` | `gid`、逗号分隔的 `wxidlist`、`msg`，实现真实群成员提及 |
| `/SendFileMsg` | `toid` 加 `path`，或 `fileData` 十六进制数据加 `fileName`；覆盖图片、GIF、MP4 和普通文件 |
| `/SendImgMsg` | 保留为旧接口兼容入口，转入文件发送流程；在兼容说明中标明迁移 |
| `/SendImgMsg_NoSrc` | 使用 CDN 返回的 `fileid`、`authkey`、CRC、MD5、大小和接收方发送图片 |
| `/SendFileMsg_NoSrc` | 实现文档中的文件路径或 hex 数据、`clientmsgid`、文件元数据及相关场景参数 |
| `/ForwardXMLMsg` | 统一承载图片、视频、GIF 的 XML 转发，接受 `toid/content`，兼容源码的 `to_wxid` |
| `/SendVoiceMsg` | 接受 SILK v3 路径或 hex 数据及语音时长；遵循文档 `fileData` 优先级，不内置音频转码 |
| `/ForwardVoiceMsg` | 按文档接受接收方、语音 URL/fileid、AES key 和时长，使用有效资源完成转发 |
| `/SendPatMsg` | 私聊拍一拍，以及 `gid` 指定群聊的拍一拍 |
| `/SendFinderMsg_NoSrc` | 视频号 XML 消息，支持文档的 `msg/xml` 与场景 `uuid` |
| `/SendCardMsg_NoSrc` | 卡片 XML 消息，支持文档的消息类型参数 |
| `/upload` | 实现无源发送需要的 CDN 上传；使用当前客户端会话，返回实际文件标识和元数据 |
| `/client_hook/status` | 引擎、账号、接收状态、队列及存储水位、回调错误、能力验证状态 |
| `/client_hook/requests/{request_id}` | 查询某次发送或上传的持久化状态与结果 |

类型和参数进一步对照各页示例建立本地接口清单与 OpenAPI，并固定查阅日期。文档标注与示例有冲突时，在清单中给出最终可验证约定。CDN 标识、AES key 和超过 JavaScript 安全整数范围的值采用字符串表达，不将密钥转为数值。MD5、CRC、大小和扩展名以实际文件核验。调用方必须提供有效 XML 或已有资源参数；不能使用虚构的 CDN 数据实现表面成功。

文件路径指服务所在 Windows 主机上的文件。hex 数据先在本模块管理的临时目录生成自有文件，等待异步操作完成后再清理；结果未知时不能提前删除输入。默认路径文件上限 100 MiB、hex 解码后上限 16 MiB、JSON 请求体上限 34 MiB，允许通过配置调小或调大。文本和 XML 默认上限为 UTF-8 编码后 64 KiB，超过限制明确拒绝，不截断发送。

### 原生调用和发送结果

所有业务操作进入有界调度队列，默认最多等待 64 项；队列满返回 429。在已核实的客户端执行队列上运行，动态定位并验证上下文，不硬编码历史线程 ID 或地址。按能力分别核对入口指纹、ABI、对象构造、字符串、引用计数、上传回调和提交结果。

每次发送创建独立输入对象并正确转移所有权，支持连续发送、长字符串和非空内部缓存场景。保留既有接收会话的隔离、draining 和入口恢复逻辑。账号变化后拒绝旧账号上下文的新业务操作，并使未提交请求失败；已提交操作保留其实际结果或未知状态。

请求支持可选 `request_id`，未提供时由服务生成；ID 与规范化参数摘要和账号绑定后持久化。相同 ID、相同内容返回原操作，相同 ID、不同内容返回 409。幂等记录默认保留 7 天，明确告知过期后不能保证去重；超过期限的结果未知操作仍保留，直到显式处理。

操作状态为 `queued`、`running`、`accepted`、`failed`、`unknown`。先持久化提交意图再执行原生调用；服务在提交附近崩溃时，无法证实结果的操作进入 `unknown`，不能自动再次提交。启动恢复可继续执行确认尚未调用的 `queued` 项；`running` 项按未知结果恢复，优先查询既有原生操作。

发送接口最多同步等待 2 秒，未完成返回 HTTP 202 和 `request_id`；查询接口继续跟踪同一次操作。已在本地接受返回 `ret=0`、`retmsg="success"`、`state="accepted"`，并明确 `delivery_confirmed=false`。失败返回非零 `ret`、稳定的 `error.code` 和说明；不得用本地接受冒充对方收到。微信内部异步资源状态未完成时也不能提前标记成功。

JSON 语法或参数错误使用 400，未授权使用 401，未知资源使用 404，状态冲突使用 409，请求体过大使用 413，限流使用 429，原生业务失败使用 502，客户端未就绪、账号未知或能力未适配使用 503。错误体带 `error.code/message/retryable`，已创建的操作带 `request_id`。能力未实现时必须报错，不以空结果或固定成功响应占位。

旧固定文本实验的一次门限与历史证据保留，不删除、不绕过、不复用作新通用接口。升级原生协议版本；已加载的不兼容 DLL 要求正常重启客户端后部署，禁止强制卸载或覆盖。

## 消息持久化与未消费消息

这里的“未读”定义为指定 agent **尚未确认消费的事件**，不等同于微信界面的未读数，消费者确认也不修改微信已读状态。新增独立 `read/mark` 执行原生会话已读，不能混入消费确认。本期默认采集所有私聊和群聊的新到达文本，允许服务配置会话过滤；后续将同一机制扩展到文档规定的其他入站消息类型。过滤在采集侧统一生效，本期不同消费者读取同一份采集范围，不提供消费者独立过滤规则。

数据流为：微信 Hook → 有界自有快照 → Python 收集器 → SQLite 提交 → 唤醒等待者 → agent 处理 → 显式确认。仅在 SQLite 提交后才对 HTTP 消费者可见。SQLite 使用 WAL、事务和完整同步设置，消息与消费进度分开保存，服务重启后恢复。单个状态目录只允许一个服务实例写入。

每条事件包含本地 `event_id`、账号、客户端实例、采集时间、类型、会话 ID、方向和已核实的发送者/接收者字段。`event_id` 使用数据库实例 UUID 加单调序号，跨服务重启稳定；它用于本地投递去重，不冒充微信消息 ID。只有核实后才提供真实 `msgsvrid`、微信消息时间、`msgsource` 和群成员字段，不填猜测值。文本快照扩展到配置上限并检测完整性，超长消息记录明确的采集错误，不静默输出截断正文。

事件格式从本期开始明确 `message_type` 和类型对应的 `payload`，文本正文不能成为所有消息类型的唯一承载字段。后续附件事件扩展文件名、大小、资源标识和下载/解码状态，不把图片、语音或文件强转为文本。不要求本期预先实现未验证的原生字段或空壳下载接口。

保留 `generation/seq` 供原生诊断；同一底层微信消息若被重复观察，未取得可靠微信消息 ID 前不承诺业务去重。队列协议保证本地事件可重复投递，agent 以 `event_id` 去重；不能保证业务动作恰好执行一次。

### 长轮询和确认接口

| 接口 | 行为 |
| --- | --- |
| `POST /consumers` | 创建或取得消费者；必填稳定 `consumer_id`，首次创建可选 `start=earliest/latest`，默认 earliest；已存在则沿用进度 |
| `GET /messages?consumer_id=…&timeout=30&limit=100` | 从已确认位置读取下一批；可带上次 `next_cursor` 校验进度，未带则使用服务器进度 |
| `POST /consumers/{consumer_id}/ack` | 提交当前批次 `ack_token`，原子推进该消费者进度；重复确认同一 token 幂等 |
| `GET /consumers/{consumer_id}` | 查询已确认位置、待确认批次、积压和过期缺口 |
| `POST /consumers/{consumer_id}/reset` | 显式选择 earliest 或 latest 重置位置、撤销旧批次并记录跳过范围；常规 SDK 不自动调用 |

`timeout` 范围 0–30 秒，0 表示立即返回；`limit` 范围 1–100。创建消费者时绑定当前数据库与账号。读取时账号不一致返回 409，换号必须显式创建新消费者或重置。未登录期间查询状态可以成功，消息读取明确报告接收暂停，不把暂停当作正在持续采集。

返回包含 `events`、`next_cursor`、`ack_token`、`has_more` 和采集状态；空批次不产生确认 token，也不推进进度。有可读消息时立即返回，没有时在提交后唤醒或超时返回空数组，不使用固定间隔扫描模拟长轮询。

每个消费者最多一个未确认批次和一个等待请求。未确认时再次取消息返回同一批次和 token；并发读取冲突返回 409。批次内容和 token 持久化，重启后仍可确认或重取。仅接受当前批次确认，不允许客户端提交任意更大的游标跳过消息。过时游标、其他消费者 token 和重置前 token 明确拒绝。

SDK 的默认流程为：注册消费者 → 长轮询 → 将事件交给业务处理器 → 整批处理成功后 ack → 下一轮。处理失败或进程退出时不确认；下次继续获取该批次。处理一批后崩溃可能导致已处理事件重投，示例必须演示按 `event_id` 去重，以及外部副作用与本地确认之间的边界。

### 保留期限和采集缺口

默认事件保留 7 天，消息存储逻辑容量上限 1 GiB，均可配置。先清理所有消费者已确认的最老事件；达到时间或容量硬限制时可清理未确认事件，但必须保留缺口元数据。SQLite WAL 定期检查点并复用空间；状态、错误日志和已完成操作记录也按期限清理，不能承诺数据库物理文件始终精确小于容量阈值。

消费者位置落入已清理范围时，`GET /messages` 返回 410 `cursor_expired`，附仍可用的最早位置、最新位置及已记录缺口；不自动前移。必须显式 reset 后才能继续。初始化消费者选择 earliest 只取得现存保留消息，不触发微信历史读取。

磁盘写入失败、原生队列溢出、账号切换、服务退出和客户端断开均记录状态与已知丢失计数；遇到无法继续可靠保存的情况停止采样并恢复入口，不能继续宣称消息已经持久化。重启时根据未正常结束的会话标记给出采集覆盖缺口；只能报告已知边界，不能虚构具体丢失消息条数。

本期服务只覆盖运行期间实际采集的消息。服务停止时微信收到的消息、服务启动前的历史未读和进程崩溃前尚未落盘的原生队列内容，本期不保证补取；后续历史消息阶段补齐相应查询与恢复能力。文档和状态接口必须清楚表达当前阶段的覆盖边界。

### 后续非文本接收与历史消息

后续能力与发送类型一起对齐文档，不只提供发送接口。实施前按文档逐项建立接收消息结构、下载、解码和历史消息接口清单，并针对 4.1.9.30 验证，不直接套用 4.1.10.27 的结构和偏移。

- **非文本接收：** 私聊与群聊都要获得正确消息类型、会话归属和文档要求的资源信息；与文本共用持久化、消费者、长轮询和确认机制。收到消息与附件已经下载分别表示，下载失败不删除消息事件。
- **下载与解码：** 提供图片、语音和文件的适用资源下载能力，以及文档对应的图片解码、语音数据获取；异步任务可查询状态，结果指向服务管理的实际文件。验收文件可打开、图片可显示、语音可播放，并核对错误资源、过期资源和失败重试的行为。
- **历史消息：** 提供按会话查询与分页，覆盖客户端实际可取得的历史记录；明确时间、类型和数量过滤及数据覆盖范围。服务启动前的历史未读与服务运行期间的未消费队列分别说明，不能通过本地消费者游标推断微信历史已读状态。
- **历史补取：** 由调用方显式请求后将历史记录纳入消费流程，标记来源为历史；依据已验证的微信消息标识处理实时与历史的重复。没有可靠标识时明确重复风险，不用相同正文去重。历史查询本身不自动推进 agent 消费进度或修改微信已读状态。

后续阶段必须说明微信本地记录缺失、附件过期和客户端未保留内容的限制，不能保证恢复客户端自身已不可取得的消息。

## HTTP 回调与 NDJSON

沿用启动配置 `StartPort`、`CallBackURL`、`RecvType=1` 的含义；本期不提供 WebSocket 和原始 PB 回调。配置回调地址后，使用独立持久化消费者投递，不推进任何 agent 消费者的进度。

回调外层采用文档的 `ServerPort/selfwxid/sendorrecv/msgnumber/msglist` 结构，每次一条事件，附加本地 `event_id`。本期提供文本回调，后续按文档补齐图片、语音、文件等结构；只填经过验证的 `fromid/toid/msgtype/msg` 等字段，缺少的可选字段省略，群聊会话和群成员分别表达。时间明确区分采集时间与微信消息时间。

回调请求超时默认 5 秒，HTTP 2xx 视为接受并确认；业务返回体不作为新的消费协议。失败时保留未确认批次、暂停回调消费者并记录错误，不自动重试。提供 `POST /client_hook/callback/resume` 显式恢复同一批次；即使对方已处理但响应丢失，也可能重复投递，接收方按 `event_id` 去重。修改 URL 不自动重置消费进度，保留期限和缺口规则与其他消费者相同。

NDJSON 保留现有事件字段和启停方式，新增字段采用兼容扩展。它与消息队列的可靠消费语义分别说明：标准输出本身不代表持久确认。agent 的默认接入推荐 Python 客户端 `listen` 或 HTTP 长轮询，回调用于已经有 HTTP 接收端的集成。

## 实施顺序和验证

2. **本期文本闭环。** 实现全会话文本采样、通用文本发送、SQLite、长轮询、确认、回调、SDK 与 OpenAPI。文本发送支持独立参数、多次调用、正确原生线程与对象所有权；消息在落盘后立即唤醒等待者。
3. **本期验收交付。** 完成真实私聊和群聊文本双向验证、持久消费和重启恢复测试，更新使用说明和能力矩阵。本期到此完成，不要求先实现其余消息类型。
4. **后续附件与 XML。** 实现图片/GIF/MP4/普通文件发送和文档对应的非文本接收、资源下载与图片解码，补齐 XML 转发、卡片和视频号；验证异步资源生命周期。

6. **后续历史消息与总体验收。** 实现历史查询、分页和显式补取，验证与实时队列的归属和去重，完成所有约定消息类型及配套能力的真实验证。

每个阶段都提交可运行结果，分别记录“本期文本闭环完成”和“总体范围完成”，不把两者混为一谈。为每项收发、下载、解码和历史能力记录 `not_implemented`、`fixture_verified`、`live_verified` 或 `blocked`，记录交付阶段、适配版本和具体原因。若目标版本缺少对应入口或调用证据不足，明确保留为未完成项，不悄悄删除或替换成不同操作。

### 必须通过的测试

本期执行下列测试中的文本、基础接口、持久消费与生命周期部分；附件、其他发送类型和历史相关测试作为后续对应阶段的验收要求。

- 接口参数、别名冲突、错误码、请求限制、OpenAPI 与实际响应一致；未适配功能绝不固定返回成功。
- 所有发送类型的参数适配和真实 native fixture；文本 Unicode/emoji、群 @ 成员、连续发送、超时、重复 ID、进程中断、对象释放与异步上传回调。

- 多消费者互不影响、长轮询及时唤醒、超时空返回、并发读取冲突、处理前后崩溃、重复确认、错误 token、服务重启续取、账号隔离和错误游标。
- 7 天与容量清理用可控时钟和小容量测试，验证未确认批次过期后返回 410、显式 reset 和缺口状态；覆盖磁盘写入失败、队列满及服务异常结束。
- 保留已有重复启停、draining、控制端崩溃、入口恢复、版本不符拒绝和驻留复用回归，增加收发同时运行及长轮询高并发下发送接口仍可响应。
- 无消息时请求保持等待，新消息落盘后立即返回，不等满 30 秒；本期正常负载下从采样快照入队到本机长轮询响应完成的 P95 目标为 1 秒以内。agent 离线后恢复可获取保留期内未确认消息，不需要定时任务。

## 交付标准

本期交付文本收发与基础接口的模块内完整源码、构建入口、OpenAPI、Python SDK/CLI、回调与持久长轮询示例、兼容清单和测试报告。用户只需启动接收服务，agent 通过稳定消费者 ID 即可实时或伪实时获取并确认最新未消费文本消息，无需另写定时任务；agent 离线期间由服务继续保存采集到的消息，保留期限内支持重启续取。

后续按同一标准补齐文档消息类型的发送与接收，以及下载、解码和历史消息查询/补取。最终验收以完整范围为准，本期交付说明必须列出尚未交付项。

MCP 不作为首期依赖；后续需要时在相同 HTTP/SDK 上增加适配层，不复制业务实现。
